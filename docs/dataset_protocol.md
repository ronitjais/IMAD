# Dataset protocol and source review

This review records source-page facts checked on 2026-10-25. Recheck terms and access before downloading. Dataset schemas, labels, and access may change. No dataset was downloaded in this workspace.

| Dataset | Intended use | Verified facts and constraints | Current suitability |
|---|---|---|---|
| [GenImage](https://github.com/GenImage-Dataset/GenImage) | Primary image training/internal validation/test | Official README documents `<generator>/{train,val}/{ai,nature}/...`, names eight generators, describes `ai` as AI-generated and `nature` as ImageNet-collected, and links a [Google Drive archive](https://drive.google.com/drive/folders/1jGt10bwTbhEZuGXLyvrCuxOI0cBqQ1FS?usp=sharing) and Baidu archive (Baidu code `ztf1`). The repository's [dataset license/terms](https://raw.githubusercontent.com/GenImage-Dataset/GenImage/main/License) state CC BY-NC-SA 4.0 plus additional terms, for noncommercial academic/research/teaching/scientific-publication use; commercial use of data or derivatives is prohibited. File paths expose generator, split, and class; README does not document a per-image metadata table. The README's example tree includes train/val; the linked paper data may describe testing sets, so the parser also recognizes `test` if present in an actual archive. | This is AI-generated vs ImageNet-collected, not general authenticity. Preserve official validation and test folders. If no test folder exists, create internal test only from official train. |
| [DiffusionForensics / DIR](https://github.com/belkhir-nacim/DIR) | Independent image evaluation | Official repo describes DiffusionForensics with train/val/test, domains (e.g. LSUN, ImageNet, CelebA-HQ), and `real` plus generator folders. Download requires Baidu password `dire` or RecDrive access. The page describes diffusion-generated detection; it does not provide a general manipulation label. A data license was not clearly surfaced in the README. | Potentially suitable after confirming downloaded files, reuse terms, and collapsing generator labels to fake; held out from tuning. |
| [NIST OpenMFC](https://mfc.nist.gov/) | Independent image evaluation | The site did not load during this review. Access, task definitions, and evaluation data conditions remain unverified. | Blocked pending site/data access and task schema review. |
| [M4 / SemEval-2024 Task 8](https://github.com/mbzuai-nlp/SemEval2024-task8) | Primary text research | Repository README describes full-text binary authorship plus mixed-text and multilingual subtasks. It notes held-out/unseen generators/domains/languages in evaluation and disallows extra data for the competition task. Repository shows Apache-2.0 license, but verify the particular data files and competition terms before reuse. The benchmark is broader than English binary text classification. | Use only compatible full-text binary subset, preserve language/domain/generator metadata, and respect official splits. |
| [RAID](https://github.com/liamdugan/raid) | Independent text evaluation | Repo describes over 10M generations across models/domains/decoding/adversarial attacks. It documents labeled train and extra splits; test is listed without labels. Download available via its package/Hub. Verify the current data card/license and whether labels are available for the chosen evaluation slice. | Strong robustness dataset, but select labeled, compatible split and keep external. |
| [OmniFake98K](https://huggingface.co/datasets/hy1228/OmniFake98K) | Genuine paired multimodal experiments | Dataset card says ~98K image-text pairs and Apache-2.0 metadata. Example fields include `label` (real, rumor, vision_manipulation, text_manipulation, mixed_manipulation), `image_manipulation`, `text_manipulation`, `news_title`, `img_path`, `label_2` (0 real, 1 all non-real categories), and `label_5` (5-way mapping). Inspect actual configs, records, image references, and official split provenance before training. | `label_2` matches real vs non-real dataset definition, not simply AI-generated vs human; rumor is human-crafted misinformation. Paired availability and split alignment must be measured from actual files. |

GenImage-specific tooling in `src/imad/data/genimage.py` parses only the documented generator/split/class layout, normalizes `ai`/`nature` to `fake`/`real`, and retains source folder, official split, and relative-path sample ID. Metadata-only inspection counts path-level labels without opening files; sample inspection is stratified by split/class. Manifest generation verifies every image, computes SHA-256 and 64-bit difference hashes, rejects duplicate groups crossing official splits, and deduplicates repeats. If an official test exists, it is preserved. Otherwise, when multiple generators with both classes are available, one complete generator (including its official train/val records) is held out as internal test; remaining official train/val records become train/validation. For one-generator subsets or inadequate source coverage, official validation remains validation and internal test is reserved from official train by hash group. Equal dHash within a class is a conservative near-duplicate cue; it can collapse same-class collisions, and it cannot guarantee detection of every semantic/edited near duplicate. The generic starter inspector/splitter remains for simple exploratory directory layouts and should not be used to make a GenImage manifest.
